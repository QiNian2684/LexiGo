# LexiGo 3.5.0

个人使用的英语词库与复习软件。支持 Windows 10/11 x64 和 Android 9 及以上。两端共用词典、SQLite 表结构、数据交换格式和复习逻辑。

## 使用

Windows 运行对应版本的安装程序，先选择程序位置，再选择数据文件夹和桌面快捷方式。默认程序位置为 `%LOCALAPPDATA%\Programs\LexiGo`，默认数据文件夹为程序目录下的 `Data`。直接运行 `LexiGo.exe` 也可以使用便携模式。Windows 使用 WebView2 Runtime，窗口配置保存在数据目录的 `WebView2` 子目录。Android 安装 `LexiGo-Android-3.5.0.apk` 后打开「LexiGo」。运行无需安装 Go、Python 或数据库服务器。

启动时显示可滚动的使用手册。手册配有操作截图，涵盖添加单词、每日记忆与长期掌握、词库、统计、设置和备份迁移，并显示本平台的快捷键或手势。勾选「以后不再提示」并点「确认」后，可以从「设置 → 使用说明」随时重开。

1. 在「添加单词」粘贴英文或通过「导入 TXT 文件」打开词表，点击「预览导入」，核对新增及重置数量，再确认。
2. 在「复习」点击「开始复习」。Windows 的 Enter 展开释义，1 没记住，2 记住了。点「没记住」先保存一次遗忘并留在原卡片，同时禁用「直接完成今日记忆」。点「下一单词」或再按 1 只翻页。两颗作答按钮固定在底部。点卡片右上角的「直接完成今日记忆」可立即完成该词当天目标，展开或收起释义时都能使用。Android 展开释义后左滑可记住，记录遗忘后左滑只翻页。在复习页从左向右滑动可撤销上一次作答，回到上一词并展开释义，可以重新选择。手势可从卡片外开始。Windows 可点击「撤销上一次」或按 `Ctrl+Z`。通过导航离开复习时会保存已有进度。
3. 展开卡片即可写多行个人备注。在「编辑卡片资料」可修改释义、例句等内容，停笔约 0.6 秒、失去焦点或完成编辑时自动保存。普通设置会在选择或填完有效数字后自动提交。
4. 「词库管理」可搜索、排序、筛选、修改英文拼写和资料。Windows 把鼠标停在词条上、Android 长按词条，均可打开详情预览，也可从更多菜单选「预览词条」。删除会移入回收站。选择「提前复习」可查看已掌握卡片，选择「重新学习」会重置当天和长期进度。可选中多条或全选筛选结果，再批量处理。
5. 「设置」可分别改每日复习词数、当天连对次数、长期掌握所需累计天数、音标显示及联网补充。界面会在找到系统的本地英语语音时显示发音按钮。词库行可以从更多按钮或 Windows 右键打开操作菜单。
6. 「设置 → 外观」可选择浅色、深色或跟随系统，选项立即应用并记在本机。可用导航回到当前复习卡。从设置返回会保留已展开的释义和备注。界面规范及平台细节见 [UI-DESIGN.md](UI-DESIGN.md)。
7. 「设置 → 学习 → 考试日期」可选择每年循环或指定日期。两种模式共用一个日期框，切换模式时保留所选月日。指定日期会记录日历所选的年份。复习页显示剩余自然日。默认每年 12 月 20 日，循环的 2 月 29 日会走到下一次实际的闰日。考试日期随完整学习数据迁移。旧备份缺少日期时自动使用默认值。

## 离线记忆联想

卡片在中文释义下方统一显示「记忆联想」。程序将已有构词来源和本地字形线索合并，优先选择在当前拼写中出现的前、后缀和词干。通常直接显示三条，其余在「更多联想」中查看。显示的内容用于记忆，包括字形线索。现有词库会直接使用新版索引，释义、备注和历史无需迁移。资料来源及署名见 [Morphology-1.9.txt](licenses/Morphology-1.9.txt)。

## 双层复习规则

- 默认每天的常规额度为 20 个不同的词，设置提供 40 词档位以及自定义数量。首次完成一个词的记忆需要在同一个学习日连对设定次数，默认 3 次。长期掌握默认需要累计完成 6 个学习日，可在设置修改。达到目标的那个完成日须首答「记住了」才算长期掌握。首答「没记住」时，该学习日完成后照常累计，词会顺延到后续学习日。
- 完成过记忆的词在之后的学习日第一次出现时，选「记住了」即可完成当天的记忆。首答选「没记住」则当天需按设置连对，期间再次答错会清零当天连对。退出再打开可继续当天的连对进度。
- 跳过学习、当天没轮到这个词，或答过但当天还没完成记忆，均保留累计完成天数。每个词同一个学习日最多计 1 天。
- 完成当天记忆的词退出今日队列。今日进度按完成的不同单词数计算。同一个词可能需要多次作答。重测目标约为 15 张其他卡片，优先安排不同的词。尚未作答就退出或只打开复习页不会消耗间隔。剩余候选少时，优先展示等待最久的卡片。
- 重复录入和手动重新学习会重置该词的当天连对次数、今日记忆状态、累计天数及掌握状态。资料、备注和历史仍保留。某词当天已经计入 1 天时，重置后再次完成也不会重复计入。
- 修改连对次数后，需要多次作答的词按新门槛计算。降低门槛时，已经连对到新目标的词会标记为已完成当天的记忆。完成过的词保留当日记录。调低长期掌握所需天数时，已达到新目标的词会立即标为「已掌握」。已经掌握的词保留掌握状态。
- 在「设置 → 学习日结束时间」可选择设备本地的换日时刻，默认为 05:00。延后换日时间时，已开始的学习日会继续。跨过边界时，正在显示的卡片先完成当前作答，之后切到新学习日。正在等待「下一单词」的上一个学习日卡片也可先结束。新写入的记录保留实际时间，旧记录沿用当时存下的日期。
- 新导入和重新导入的当日待学词优先首次出现。所有这些词都进入本次学习日的任务，可以超过常规上限。已经打开的当前卡片仍可作答，重测就绪的词会按原有间隔穿插。重新导入会保留资料和备注。
- `Ctrl+Z` 撤销今天最后一次仍可撤销的答题，并回退其连对、累计完成天数、队列和统计。原答题记录保留并标注已撤销。

## 易错词回顾

每个学习日按恰好五个学习日前的答错次数，选出最多 10 个词。已掌握的词也可进入回顾。每个入选词每天检查一次，答对通过，答错顺延到下一学习日。同一个词当天也在常规复习队列时，首答同时作为回顾结果。撤销的作答和单独的易错词回顾作答不计入五天后的选词。

## 当天重测顺序

每次作答后，还没完成记忆的词根据今天的作答位置安排重测。目标位置在相邻两个同词之间预留 13～17 张其他卡片。等待稍久的词会优先出现，通常间隔落在 12～18 张。到点的重测继续穿插在新词之间。跨 05:00 后，上一学习日还没完成记忆的重测词优先占用当天空余的旧词名额，间隔参考已记录的答题顺序。

重开程序或重新进入复习时，会用今天已经存下的答题历史恢复相对位置。作答历史、当日进度、长期掌握和已有备份沿用同一格式。1.2 的便携词库无需转换即可继续使用。

## 高分屏布局

复习页跟随窗口的逻辑视口宽度。宽窗口左列显示释义和例句，右列放备注和附加资料。长备注随内容增高，复习正文独立滚动，作答栏固定在窗口底部。窗口缩小时，双列自动改为单列。复习时顶部显示今日进度和日期。当天任务全部完成后显示「今天的任务已完成」。

## 文件导入

每批最多 1,000 项。纯英文可用英文逗号、中文逗号或换行分隔。内部空格允许出现在短语中，大小写和首尾空格在查重时忽略。TXT、CSV、JSON 用 UTF-8。导入新词时，文件中的完整资料优先于词典内容。再次导入已有词的作用是重新学习，原资料保留，更新内容可用编辑入口。

有表头的 CSV 可以使用以下格式。只有 `word` 是必填列，其他列可按需要提供。

```csv
word,meaning,pos,ipa,ipaUK,ipaUS,examples,exampleTranslation,etymology,collocations,note,personalNote
crucial,至关重要的,形容词,,,,This is a crucial decision.,这是一个至关重要的决定。,,,,重点记住关键的
```

JSON 词表是对象数组，也可以用相同的字段名。

```json
[
  {"word":"fiscal","meaning":"财政的","pos":"形容词","personalNote":"财政政策"}
]
```

## 查词策略与来源

- 离线 ECDICT 可提供基础中文释义和音标。词性从其结构化释义标记提取。内置索引有 758,516 项。原始版本为 `39cfb9672c0906b63569e0453c2e6abfb9ab182a`，以 MIT 许可分发。https://github.com/skywind3000/ECDICT
- 例句按导入拼写查找。动词的过去式、过去分词和 `-ing` 形式可以直接匹配包含该词形的句子。已有中英句对优先，内置语料来自 Tatoeba、Wiktionary 和 Simple English Wikipedia。部分例句在构建时用 OPUS-MT 补译，可离线查看。[例句来源与数据许可](licenses/Dictionary-data-notices.txt)
- 开启「设置 → 词典 → 联网补充缺失的词典资料」后，导入和查看卡片均可触发后台补全。程序通过英文 Wiktionary、Tatoeba 和 Wikipedia 查找含相同词形的公开例句。没有现成中文译文时，提交经来源验证的公开英文例句给 MyMemory。联网补全无需账号、密钥或付费。
- 已取得的资料会保存到本地。机译译文会标注「机译」。自填资料和备注保存在本机。断网或服务限额期间仍可复习，也可手动补充。[MyMemory 服务说明](https://mymemory.translated.net/doc/usagelimits.php)
- 自动补充的例句译文使用内置 [OpenCC 词表](licenses/OpenCC.txt) 转为简体中文。升级或恢复备份时，能与原始例句库对应的旧译文也会转换，手工填写的译文保留原文。
- 原创双语例句和记忆提示作为内置学习资料提供。第三方词条来源和许可可在界面查看。

## 本地数据与恢复

词库为所选数据文件夹里的 `vocabulary.db`，便携版默认使用 EXE 同级的 `Data`。设置、词条和复习记录统一保存在 SQLite，程序启动时初始化数据库。目录不可写时会显示实际路径和错误。安装时选择的路径保存在程序同级的 `LexiGo.data-dir`。

### Windows 升级

1. 关闭旧版背词本。若旧进程还在后台，等它退出，或在任务管理器中结束旧版进程。
2. 在安装向导中选择旧程序目录和原数据目录，即可继续使用已有词库。全新安装可以使用尚未创建的路径，例如 `D:\lexigo` 和 `D:\lexigo\data`。确认安装后，向导创建目录并检查写入权限。便携版可直接替换 EXE，保留同级 `Data` 及已有的目录设置。若选中的数据目录没有词库，新版会尝试从 `%LOCALAPPDATA%\WordReview\vocabulary.db` 创建一致性副本，并通过完整性检查后保存。原文件留在原处。
3. 如果两处已有不同的数据库，新版会使用选中目录的词库并显示提示。要换用旧库时，可以分别备份两边，再从含有需要的数据的程序导出学习数据，在新版确认覆盖。
4. 首次读取旧规则数据库时，先写入 `Data\backups\before-dual-memory-v2-*.json`，再用一次 SQLite 事务升级。旧词条、设置、备注、答题历史和已掌握状态保留。旧规则记住次数在词库里单独标注，当前未掌握词的双层进度从零开始。旧版导出的 JSON 仍可恢复，并应用相同的兼容规则。

移动便携版之前，关闭程序，再一起移动 EXE 和整个 `Data`。使用独立数据目录时，可重新运行安装向导选择原目录。程序运行中不要只拷贝 SQLite 主文件，因为最新提交可能还在数据库的 WAL 中。

### Windows 卸载

通过「设置 → 应用 → 已安装的应用 → LexiGo → 卸载」打开确认页。卸载会删除程序、当前安装所用的词库、笔记、复习记录、本地自动备份、设置和缓存，并清理安装创建的快捷方式及注册表项。请先导出想保留的数据。保存到其他位置的导出文件会保留。

### 备份

在「设置」点击「备份数据」可保存包括词条、备注、历史、回收站和设置的完整备份。「恢复备份」先要求确认覆盖范围，然后事务恢复。恢复前的快照写入 `Data\backups\before-restore.json`。旧版留有恢复前快照时，迁移也会尝试复制为 `Data\backups\legacy-before-restore.json`。

日常词表交换可用「词库管理」里的 CSV 导出。本地备份以 `.lexi` 为后缀，内容仍是 JSON，请通过「恢复备份」加载。

### 在 Windows 和 Android 间迁移

1. 在当前设备打开「设置」。Windows 选择「导出数据」，Android 点击「导出数据」后选择「分享数据」或「保存到手机」。文件名使用本机时间，默认类似 `LexiGo-2026-11-20-09-07-03.lexi`。
2. 自行把文件传到另一台设备。打开「设置 → 导入数据」，并选择 `.lexi` 文件。
3. 检查生成时间、词条和今日任务摘要。选择「确认覆盖」后，程序自动备份接收端，再用文件中的完整状态替换接收端。想回到覆盖前的状态，可用同一入口导入这份自动快照。
4. 换回原设备时，在正在使用的设备上重新导出最新文件，再在原设备导入。

完整学习数据会保存当天任务及调度所需的已提交作答历史。两端仍处于同一个学习日时，可以继续已有任务。导入已结束学习日的快照时，按原跨日规则开始本机当前学习日。跨时区导致两端日期不一致且导出端学习日尚未结束时，等该学习日结束后再导入。自动快照位于应用数据目录的 `backups/before-transfer-*.json`。

Android 数据保存在应用私有目录 `files/StudyData`。卸载应用或清除应用数据之前，请用「导出数据」把快照保存到应用外。导入后可通过「导出覆盖前备份」将最近一次自动快照取出，再用「导入数据」恢复。完整数据含个人备注，请自行保管。

Android 3.5.0 使用独立的包名和已保存的新发行签名，可与 3.3.1 共存。请在旧版导出 .lexi，再在新版导入。此后同一包名和证书的版本可直接覆盖升级。

## 构建与测试

使用 Go 1.25 或更新版本和支持 `amd64-unicode` 目标的 NSIS 3.11 或更新版本。若 `makensis` 不在 PATH，可通过 `-MakeNSIS` 指定 `makensis.exe`。在 Windows PowerShell 执行以下命令。

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

脚本运行 Go 测试并生成便携版 `dist\LexiGo.exe` 和安装版 `dist\LexiGo-Setup-3.5.0.exe`。首次从源码构建需要取得 `go.mod` 和 `go.sum` 声明的依赖。已编入的词典、界面和应用图标无需重新下载。第三方依赖许可证见 `licenses/`，数据处理脚本在 `scripts/`。

也可用 `go test ./...` 单独测试核心规则。用 Python 3 运行 `python scripts/test_http.py 路径\LexiGo.exe` 可以在独立临时词库上测试离线工作流和中止进程后恢复。还可运行 `python scripts/test_portable.py .\dist\LexiGo.exe`，用独立临时目录验证 EXE 路径、移动后重新打开和隔离的旧库迁移。脚本经过 EXE 的 `--serve` 模式测试后端，WebView2 窗口的验证需在 Windows 上双击 EXE。

Android 的开发环境、签名方式和命令见 `android/README.md`。两端快照共用 `transfer.go` 中的版本化协议。文件是 UTF-8 JSON，SHA-256 校验针对原始数据负载字节。请直接传输文件，编辑或重新格式化可能使校验失效。文件大小限制为 128 MiB。

## GitHub 发行

在 Actions 中手动运行「Android release」即可使用仓库的 `LEXIGO_ANDROID_SIGNING` 加密配置构建 Android 包。选择发布时，流程会先校验签名，再上传并重新下载草稿附件进行 SHA-256 核对。

双平台构建和发布步骤如下。

1. 在 Windows 构建机的当前用户个人证书库中准备受信任的代码签名证书及私钥。将证书指纹设为 `LEXIGO_WINDOWS_SIGNING_THUMBPRINT`，运行 `.\build.ps1 -Release`。如有需要，用 `-SignTool` 指定 Windows SDK 的 `signtool.exe`。脚本会先签署便携版，再将它打包进安装程序并签署安装程序。
2. 使用当前 Android 发行密钥库按 [Android 构建说明](android/README.md) 生成 APK 和 `.idsig`，将它们与两个 EXE 放在同一目录。把对应源码提交标记为 `v3.5.0` 并推送标签。
3. 在已登录 GitHub CLI 的 Windows 构建机上运行 `.\scripts\publish-release.ps1 -Tag v3.5.0 -AndroidBuildTools <Build Tools 35.0.0 的路径>`。脚本验证四个文件的签名和版本，将它们上传到草稿，从 GitHub 下载并逐一比对 SHA-256，全部通过后才公开发布。
